# M1: Spec and Wireframes

**Project:** Book & Notes Vault
**Author:** Bugingo Nshuti Brandon (GitHub: bbugingo-blip)
**Theme chosen:** Book & Notes Vault (catalog, pages, tags, search)

## 1. Purpose

Book & Notes Vault is a small web app for keeping a personal catalog of books and notes. A reader can record what they read, tag it, see how many pages they have logged against a reading target, and find entries quickly with regular-expression search.

It is built with plain HTML, CSS and JavaScript (no frameworks). All data stays in the browser's `localStorage`, and records can be exported to and imported from JSON.

**Primary user:** a student or reader who wants a fast, keyboard-friendly way to log and search what they read.

## 2. Sections (pages)

The app is a single page with five sections, reached from the header navigation.

| Section | Anchor | Purpose |
| --- | --- | --- |
| Dashboard | `#dashboard` | Total records, total pages, top tag, reading load, page cap message, 7-day chart |
| Records | `#records` | Regex search, sort, table (cards on mobile), Edit and Delete per row |
| Add / Edit | `#form-section` | Form to add a record or edit an existing one |
| Settings | `#settings` | Page cap, display unit, reading speed, theme, export, import, sample data |
| About | `#about` | Purpose of the app and contact details (GitHub, email) |

## 3. Data model

### 3.1 Record

Every record has a unique `id` and two timestamps.

```json
{
  "id": "rec_0001",
  "title": "Clean Code",
  "author": "Robert C. Martin",
  "pages": 464,
  "tag": "Programming",
  "dateAdded": "2026-10-13",
  "createdAt": "2026-10-13T08:00:00.000Z",
  "updatedAt": "2026-10-13T08:00:00.000Z"
}
```

| Field | Type | Rule | Notes |
| --- | --- | --- | --- |
| `id` | string | `rec_` plus 4 digits, unique | Generated as the highest existing number plus one |
| `title` | string | Required, no leading or trailing spaces, no repeated word | Rejects "The the Book" |
| `author` | string | Needs at least one letter, no digits, no leading or trailing spaces | Rejects "R2D2" |
| `pages` | number | Greater than 0, whole or up to 2 decimals, no leading zeros | Stored as a number |
| `tag` | string | Letters, with single spaces or hyphens between words | "Self-help", "Software Design" |
| `dateAdded` | string | `YYYY-MM-DD` and a real calendar date | Rejects 2025-02-29 |
| `createdAt` | string | ISO timestamp, set once when the record is created | |
| `updatedAt` | string | ISO timestamp, refreshed on every edit | |

### 3.2 Settings

| Field | Default | Meaning |
| --- | --- | --- |
| `cap` | 2000 | Page target shown on the dashboard |
| `unit` | `pages` | Display unit for reading load: `pages`, `minutes` or `hours` |
| `pagesPerMinute` | 1 | Reading speed used to convert pages to minutes and hours |
| `theme` | `light` | `light` or `dark` |

### 3.3 Storage

| Key | Contents |
| --- | --- |
| `vault:records` | JSON array of records |
| `vault:settings` | JSON object of settings |

Every add, edit, delete, import or settings change saves immediately. If stored data is missing or malformed, the app falls back to an empty list and default settings instead of failing.

### 3.4 Import and export

- **Export** downloads all records as a pretty-printed JSON array (`vault-export.json`).
- **Import** checks the file before loading anything: it must be valid JSON, the top level must be an array, every record needs a unique `id` and both timestamps, and every field must pass the same rules as the form. If any record fails, nothing changes and the user sees the first few errors.

## 4. Validation rules (regular expressions)

| Rule | Pattern | Valid | Invalid |
| --- | --- | --- | --- |
| Title (no edge spaces) | `^\S(?:.*\S)?$` | `Dune` | ` Dune`, `Dune ` |
| Pages | `^(0\|[1-9]\d*)(\.\d{1,2})?$` | `320`, `12.5` | `012`, `1.234` |
| Date | `^\d{4}-(0[1-9]\|1[0-2])-(0[1-9]\|[12]\d\|3[01])$` | `2024-02-29` | `2025-13-01` |
| Tag | `^[A-Za-z]+(?:[ -][A-Za-z]+)*$` | `Self-help` | `Sci  Fi`, `Sci-Fi2` |
| Repeated word (advanced, back-reference) | `\b(\w+)\s+\1\b` | `The Theory of Everything` | `The the Book` |
| Author (advanced, lookahead) | `^(?=.*[A-Za-z])(?!.*\d)\S(?:.*\S)?$` | `Ada Lovelace` | `R2D2`, `123` |

The regex search box accepts any pattern the user types. It is compiled inside `try/catch`, so an invalid pattern shows a message and leaves the list unchanged.

## 6. Key interactions

| Action | What happens |
| --- | --- |
| Type in a form field | Rule checked as you type; message appears under the field |
| Submit with errors | Errors shown, focus moves to the first invalid field, status says "Please fix the errors in the form." |
| Submit valid record | Record added or updated, form cleared, status announces the result, stats update |
| Click Edit | Row loads into the form, page scrolls to it, button changes to "Save changes", "Cancel edit" appears |
| Click Delete | Browser confirm dialog; on yes the row is removed and stats update |
| Type in search | List filters live; matches highlighted with `<mark>`; count shows "x of y records match" |
| Invalid search pattern | Message "Invalid regular expression. Showing all records." |
| Change sort | List re-orders by date, title (A to Z or Z to A) or pages (low to high or high to low) |
| Total pages above cap | Dashboard message turns red and is announced assertively |
| Import bad file | Errors listed, no data changed |

## 7. Responsive plan

Mobile-first: the base styles are for about 360px and larger screens add rules with `min-width` media queries.

| Breakpoint | Changes |
| --- | --- |
| Base (about 360px) | One column; Menu button toggles the nav; records as cards; 2 by 2 stat tiles |
| 768px | Nav always visible; records as a table; 4 stat tiles in a row; search toolbar in one row; settings in two columns |
| 1024px | Add / Edit and Settings sit side by side; wider padding |

One tasteful animation set: smooth anchor scrolling, a short slide for the mobile menu, a fade-in for new cards, a grow transition on chart bars, and a small lift on button hover. All animation is turned off for users who prefer reduced motion.

## 8. Accessibility plan

### 8.1 Structure
- Landmarks: `header`, `nav` (labelled "Main"), `main`, `section` (each labelled by its heading), `footer`.
- One `h1`, then `h2` for each section and `h3` for sub-headings.
- The records table has a caption, `scope="col"` headers, and cards on mobile keep the same labels through `data-label`.

### 8.2 Keyboard
- A "Skip to main content" link is the first tab stop.
- Every control is a real button, link, input or select, so Tab, Shift+Tab, Enter and Space work with no extra code.
- Every control has a visible 3px focus outline.
- After add or edit, focus returns to the Title field; after delete, focus moves to the search box.
- Touch targets are at least 44px tall.

### 8.3 Forms
- Every input has a bound `<label>`.
- Each error message sits in an `aria-live="polite"` paragraph linked by `aria-describedby`.
- Invalid fields get `aria-invalid="true"` and a thicker red border, so errors are not shown by colour alone.

### 8.4 Live regions
| Region | Politeness | Used for |
| --- | --- | --- |
| `#status` (`role="status"`) | polite | Added, updated, deleted, imported, exported, cancelled |
| `#cap-message` | polite | Pages remaining under the cap |
| `#cap-alert` (`role="alert"`) | assertive | Cap exceeded |
| `#search-error` (`role="alert"`) | assertive | Invalid search pattern |
| `#import-error` (`role="alert"`) | assertive | Import problems |
| `#result-count` | polite | Number of matching records |

### 8.5 Colour and contrast
Contrast ratios below were calculated from the palette values (WCAG: 4.5 or higher for normal text).

| Pair | Light theme | Dark theme |
| --- | --- | --- |
| Text on page background | 15.78 | 15.62 |
| Text on card surface | 17.20 | 13.91 |
| Muted text on background | 7.14 | 8.78 |
| Links on surface | 8.75 | 7.27 |
| Button text on primary | 8.75 | 7.98 |
| Error text on surface | 7.75 | 7.06 |
| Success text on background | 5.77 | 10.06 |
| Highlighted match text | 13.78 | 5.27 |

The dark-theme highlight colour was changed from `#8a6d00` (4.28) to `#7a5f00` (5.27) so highlighted text passes.

### 8.6 Other
- Highlights use the native `<mark>` element and user text is HTML-escaped first.
- The chart has a text alternative (`aria-label`) listing each day and its count.
- Search and sort never rely on colour alone.
- `prefers-reduced-motion` disables animation.

## 9. Code structure (modules)

The script files can sit beside `index.html` or in a `scripts/` folder; the path in the `<script>` tag of `index.html` must match whichever is used.

```
index.html        page structure
style.css         mobile-first styles
tests.html        browser test page
seed.json         12 sample records
scripts/
  validators.js   regex rules for the form
  search.js       safe regex compiler, highlight, filter, sort
  storage.js      localStorage and import/export checks
  state.js        records, settings, stats, cap and unit conversion
  ui.js           renders the page
  main.js         connects events to the modules
tests/
  tests.js        assertions
docs/
  M1-spec.md      this document
```
